I’ve always been curious about music models, partly because they bring together my interest in music and my full-time work in AI. With [RagaXonic](https://github.com/manaskarra/RagaXonic-DL), I worked on a three-layer LSTM for polyphonic MIDI, exploring Hindustani and Western musical ideas.

Then I read [Sparks of Weight-Space Programming](https://rikiyat.github.io/blog/weight-space-programming/). An LLM reasons about a network and writes changes into its weights, without gradient descent. The experiments include using Python and feedback from running the model. I wondered what that would look like with music.

The goal I settled on: **keep asking for piano, but make the saved model produce flute.**

## Same request, different instrument

> A solo honky-tonk piano plays a fast boogie-woogie, only piano.

Same seed and generation settings, with playback levels matched. These are recorded outputs, not live browser generation. At one point during development, my feedback was simply “it’s a flute.” Earlier pairs had both sounded like piano, or sounded worse without making a convincing switch.

GPT-6 Astra designed and implemented the main edit using Python and encoded examples. I set the goal, listened to the comparisons and steered the experiments: a human-guided WSP workflow.

## Where the change lives

Magenta encodes a prompt or reference recording as numbers describing its style. An adapter maps those numbers into a signal the generator can use. That’s the target.

<figure className="magenta-architecture" aria-label="The style-conditioning path through Magenta">
  <ol className="magenta-flow">
    <li><strong>Text or reference audio</strong><span>The same input before and after</span></li>
    <li><strong>Frozen style encoder</strong><span>Style tokens → codebook lookup → 768-number vector</span></li>
    <li className="magenta-edited-stage"><strong>Style adapter · W → W′</strong><span>768 × 1,024 weights. This is the only tensor replaced.</span></li>
    <li><strong>Music generator + audio decoder</strong><span>Newly generated music</span></li>
  </ol>
  <figcaption>The style-conditioning path, simplified. Reference audio guides new music; this does not replace an instrument in a recording note for note.</figcaption>
</figure>

Piano and flute examples give a direction, **d**, that shifts the conditioning toward flute. A second vector, **g**, controls how strongly it applies. Piano examples should activate it; other instruments should mostly leave it alone.

The gate uses 432 text encodings and nine synthetic audio references. Python solves the constraints directly, without backpropagation or optimizer steps, then writes a rank-one update:

<div className="magenta-equation" role="math" aria-label="W prime equals W plus alpha times g d transpose">
  <i>W</i>′ = <i>W</i> + α <i>g d</i><sup>⊤</sup>
</div>

The strength, α = 1.4, was chosen through listening comparisons. Ordinary inference uses the replacement matrix; its multiplication includes the control signal, without an extra instruction or activation hook.

That changes **786,432 values, or 0.032% of the full checkpoint**. Magenta already knows how to generate flute. The edit redirects when it uses that ability. The [method](https://github.com/manaskarra/magenta-wsp/blob/main/METHOD.md) explains the calculation; [Unified Concept Editing](https://unified.baulab.info/) is related prior work on closed-form edits.

## What I checked

I checked the saved model as well as the sound. The [verification records](https://github.com/manaskarra/magenta-wsp/tree/main/evidence) show:

| Check | Result |
| --- | --- |
| Compare checkpoints | One matrix changed; the other 617 tensors are identical. |
| Recalculate from saved encoder tokens | The patch hash matches exactly. |
| Reload in a fresh process | One development clip reproduced byte for byte on the tested runtime. |

I heard the switch on solo prompts, a real piano reference and a jazz trio where bass and drums were still audible. Piano-and-guitar could stay piano-and-guitar. A piano-and-strings reference was stranger: a negative gate response made the edit run backwards and add piano.

There’s an obvious baseline: just ask the original model for flute.

> A solo flute plays a fast boogie-woogie, only flute.

Two blind quality comparisons split one preference each. I was the only listener, so this doesn’t establish a quality advantage over prompting. What I can show is an audible behavior change stored in the weights, and the inputs where it fails.
